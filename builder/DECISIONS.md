# Decisions

Written 2026-10-15, before the workspace was built. Reasoning rung: context (a stage contract a
model reads once per question), with the practice rounds as the loop.

## Form

**Pipeline, one stage.** The repeating unit is one question answered in one fresh session
(brief: "What is the repeating unit of work? One question."). Every question runs the same
sequence against the same papers and emits one deliverable, the reply, which is the Pipeline
form. No record accumulates (not a Record library), the papers are not the product (not a
Knowledge bundle), and nobody will edit the papers (not a System map).

## Number of stages: one

The skill puts stage boundaries where a person pauses to check an output, and where one stage's
output file becomes the next stage's input. Neither exists here:

- Nobody is present during a run (brief: "Who else touches this? Nobody during a run").
- The session cannot write files, so there is no intermediate output to hand across a boundary
  or to edit.
- The answer goes back in one message.

Splitting "find the papers", "apply the changes" and "write the answer" into three folders would
give three contracts with no files between them and cost the model two more reads per question
for no check anyone performs. The brief says: if the method's answer is one stage, say so and
build that. It is one stage: `01 answer`. Inside its contract the work is still ordered (find,
date-check, answer, self-check), because that order is real; it is a numbered process, not a set
of folders.

What I considered and rejected: a second stage `02 check` read just before replying, to put the
answer checklist fresh in front of the model. It has no input file and no human, so it is a
paragraph, not a stage. If practice shows the model skipping the end checks, the fix is to move
or tighten that paragraph, not to add a folder.

## Where the generated document list lives

`01 answer/documents.md`. It is generated by `tools/make-map.mjs` from the papers' headers and
overwritten whole on each set of papers. The workspace ships it as a marked placeholder. It is
outside `reference/`, it is named in the root `CLAUDE.md`, in the map `CONTEXT.md`, and as an
input of the stage contract. It is a separate file because the script writes the whole file;
putting it inside a contract would overwrite the contract.

## How a run reads (the step budget)

`CLAUDE.md` loads by itself. It sends the model to read `01 answer/CONTEXT.md` and
`01 answer/documents.md` together, then the papers. That is two instruction opens per question.
The root `CONTEXT.md` (the map) is for a person or agent maintaining the workspace; a question
run does not need it, and the entry file says so.

## Departures from the skill's templates (following the PO Verifier)

1. **Folder names.** `01 answer` with a space, as in the PO Verifier (`01 intake`), not the
   skill's `01_answer` or `stages/01_answer/`.
2. **No `stages/` wrapper.** Numbered stage folders sit at the top level, as in the PO Verifier.
3. **No `_shared/`, `_templates/`, `setup/`.** The factory layer is the papers in `reference/`,
   which the harness supplies; there is nothing to configure per user and no unit to copy (a
   question is a message, not a folder).
4. **No `output/` folder and no edit surface.** The session cannot write; the deliverable is the
   reply. This breaks invariant 6 by necessity of the harness, not by choice.
5. **No human check in the contract.** The skill's contract ends in one human check. Nobody is
   present, and the brief forbids telling the model to stop and ask. The contract ends with a
   self-check the model runs on its own reply instead.
6. **Stage contract headings follow the PO Verifier** ("What this stage is for", "What comes in",
   "What goes out", "What must never happen here") rather than the skill's
   Inputs / Process / Outputs / Human check. The content each heading carries is the same.
7. **No `the-page.md`.** The PO Verifier has a page saying who it is for and why. The brief's
   house style lists router, map, stage folders and `reference/` only, and the "who and why" fits
   in the first line of `CLAUDE.md`. Adding a page would be a third instruction read for no rule.
8. **Entry file does not say "read the map first".** The PO Verifier's `CLAUDE.md` sends the
   model to `the-page.md` then `CONTEXT.md` before any stage. Here the entry file sends a
   question run straight to the stage contract and the list, to keep instruction reads at two.
   The map is still the place a maintainer starts.
9. **No `reference/` folder in the build.** The harness copies the papers into `reference/`; the
   workspace must not hold its own. `CLAUDE.md` and the map say where the papers will be.
10. **"Stop and ask" is replaced.** The PO Verifier's rule "stop and ask Sam when unsure" becomes
    "when a fact the answer turns on is missing, say which and give the answer for each case".

## Rules I hold myself to while building

- No figure, date, section number or organisation name from any practice paper appears in the
  workspace outside `documents.md`. The contract describes the kinds of trap (a summary that
  differs, an archive with old figures, a change entry with its own deciding date, a rule in a
  second document that changes the case), never the instances.
- One home per rule: the reading rules live in `01 answer/CONTEXT.md` only.
